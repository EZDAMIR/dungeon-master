# Hackathon Submission Checklist

## Required product behavior

- [ ] Webcam movement is recognized in real time in the browser.
- [ ] The primary flow works without keyboard or mouse after permission.
- [ ] At least three different gestures or movements trigger different actions.
- [ ] Recognized input has visible feedback.
- [ ] One scenario runs from first motion to final result.
- [ ] The error mode detects an imprecise movement.
- [ ] The correction says what happened and what to change.
- [ ] The evaluator does not install local software.

## Dungeon Master demo script

- [ ] Open deployed URL.
- [ ] Grant camera permission.
- [ ] Complete gesture tutorial.
- [ ] Move cursor with index finger.
- [ ] Select squat with pinch.
- [ ] Confirm with thumb up.
- [ ] Calibrate side view.
- [ ] Perform a correct repetition.
- [ ] Perform a deliberately shallow or fast repetition.
- [ ] Hear and see the concrete correction.
- [ ] Complete the set.
- [ ] View totals and error counts.
- [ ] Return to menu with fist.

## Technical quality

- [ ] Visual rules are project-owned, not only an unchanged library demo.
- [ ] Raw video is not uploaded.
- [ ] Backend and frontend builds pass.
- [ ] README contains exact fresh-clone instructions.
- [ ] README truthfully discloses pre-existing backend scaffolding.
- [ ] Commit history clearly separates scaffold and project-specific work.
- [ ] Secrets and personal data are absent from the repository.
- [ ] Production CORS and environment variables are configured.

## Submission assets

- [ ] Exact registered team name.
- [ ] Public GitHub repository link.
- [ ] Project description and selected fitness direction.
- [ ] List of recognized gestures.
- [ ] Explanation of the error mode.
- [ ] Working deployment link.
- [ ] Backup screen recording.
